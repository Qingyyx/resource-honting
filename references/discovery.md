# 资源发现：来源地图与检索路线

> 用途：用于任意领域的资源发现，尤其是陌生领域、只有描述、名称不确定、小众目标、旧版本与多次空结果。先看来源地图判断"该找谁"，再按检索路线推进；目标是提高有效找回能力，并区分身份、收录、获取和访问的缺口。
>
> 与 [routing.md](routing.md) 的分工：routing 给已知领域的现成入口；本文件给"不知道入口时怎么发现"。

## 一、来源地图

### 1. 先判断来源的角色

| 来源角色 | 应找谁 | 能解决什么 |
|---|---|---|
| 生产与发布 | 作者、开发者、研究团队、制造商、发行方、政府或公共机构 | 原始名称、版本、发布信息、规格、数据与获取入口 |
| 编目与标识 | 图书馆、登记系统、专业数据库、标准组织、行业名录 | 确认身份、专业叫法、编号、作者机构、关联版本 |
| 分发与获取 | 仓储、软件注册表、数据门户、商店、馆藏、专业市场、服务机构 | 实际内容、文件、库存、服务范围、费用和访问条件 |
| 使用与维护 | 专业协会、领域社区、使用者、维护者、问题追踪器 | 替代名称、兼容性、实际经验、迁移位置和修复线索 |
| 历史与归档 | 发布历史、旧目录、网页档案、历史馆藏、迁移公告 | 旧名称、失效链接的出处、历史存在与版本关系 |

同一站点可能承担多个角色。编目记录不等于已经取得资源，使用经验也不等于官方规格；按当前缺口选择需要的角色。

### 2. 按资源形态找入口

| 资源形态 | 优先找什么来源 | 身份与匹配线索 | 获取时核对 |
|---|---|---|---|
| 论文、报告、研究证据 | 作者/机构、学科库、期刊会议、资助项目、机构知识库 | 题名、作者、DOI、课题号、研究类型 | 全文/摘要、版本、评议状态、适用范围；深研见 deep-research-sources.md |
| 统计、数据集、表格、地图 | 数据生产机构、政府/专业数据门户、研究仓储、地理数据中心 | 指标、变量、空间范围、时间、数据集编号/DOI | 口径、覆盖、分辨率、更新、格式、许可证、下载或 API |
| 法规、标准、专利、公共记录 | 制定机关、标准组织、专利局、登记/披露机构 | 编号、名称、法域、实施/申请日期、主体 | 现行状态、全文范围、修订与法律/地区适用条件 |
| 软件、代码、模型、插件、固件 | 维护者主页/仓库、官方注册表、模型仓库、硬件支持页 | 包名、版本、模型/设备型号、依赖、许可证 | 平台架构、兼容性、发布者、原始文件、权重与代码是否齐全 |
| 手册、图纸、维修资料、工业部件 | 制造商、专业分销商、工程目录、维修/行业社区 | 型号、硬件修订、零件号、图号、接口规格 | 原理图/数据表/用户手册的区别，适用修订、尺寸、库存和地区 |
| 图书、档案、古籍、文献版本 | 出版社、图书馆、联合目录、档案馆、作者机构 | 作者、ISBN、版次、馆藏/档案号、语言、年代 | 元数据/目录/全文、借阅或访问方式、缺页与扫描质量 |
| 课程、教材、教程、考试与培训资料 | 授课机构、教师、课程项目页、开放课程目录、专业认证机构 | 课程号、讲师、学期、级别、考纲版本 | 大纲/视频/作业是否齐全、语种、先修要求、现行考纲和费用 |
| 图片、音频、视频、字体、3D/CAD、模板与设计资产 | 原作者、机构开放馆藏、对应类型的专业素材库和市场 | 作者、作品名、目录号、视觉/声音片段、文件特征 | 原文件/预览、格式、清晰度、可编辑性、适配软件、用途授权 |
| 影视、音乐、游戏及文化作品 | 作者/制作发行方、作品目录、发行平台、相关社区 | 原名、地区译名、作品编号、年份、版本、人物/情节特征 | 目录/本体/衍生内容、地区、语种、上下架、访问与购买条件 |
| 商品、设备、供应商与实物 | 制造商、专业渠道、行业名录、经销商、交易平台 | 品类专业名、型号、规格、替代料号、行业术语 | 供应主体、库存、起订量、交付地区、总价与适配性；电商评价沿用主技能约定 |
| 专家、机构、服务与解决方案 | 专业组织、机构官网、人员/服务目录、成果与项目记录 | 问题领域、资质、地域、对象、成果、服务范围 | 身份、实际能力、近期活动、可用服务和利益关系 |
| 职位、活动、项目机会、场地与本地资源 | 主办/招聘/管理方、政府/公共服务入口、专业与地区平台 | 地区、日期、主办方、职位/项目号、设施或服务类型 | 是否仍开放、名额、地点、资格、开放时间与申请方式 |

遇到表外资源时，仍从"谁生产、谁编目、谁分发、谁使用"建立来源路线。不同资源可以组合多个行，例如找设备维修课程同时涉及设备型号、课程目录和技术社区。

### 3. 已有入口示例

| 来源类型 | 可用作起点的示例 | 注意 |
|---|---|---|
| 统计与公司原始披露 | 国家统计局、对应部委、World Bank、公司 IR、巨潮、披露易、SEC EDGAR | 原始表和公告优先，聚合/估算需回溯 |
| 学术与科学数据 | 学科专属库、Crossref、DataCite、Zenodo、机构知识库 | 目录、引文、全文与原始数据各自核对 |
| 软件与模型 | 项目官网、维护者 GitHub/GitLab、对应包注册表、Hugging Face | 核验具体维护者、发布记录、版本与依赖 |
| 图书与档案 | 出版社、国家图书馆、WorldCat、Internet Archive、Project Gutenberg | 馆藏和快照不保证全文当前可获取 |
| 创作资产 | 作者站点、Wikimedia Commons、Openverse、专业资产库 | 核对原文件页和逐项授权 |
| 文化作品与社区 | 发行方、Bangumi、MusicBrainz、SteamDB、PCGamingWiki、专业 Wiki | 分别用于身份、目录、历史或经验，不作整个平台的可信保证 |

示例不是白名单，也不是每次必须访问的清单。其他领域优先按前述方法现场发现其专业来源，而非强行套用熟悉的平台。现有源的判断参考 [platform-trust.md](platform-trust.md)。

### 4. 从领域知识扩展来源

先提取领域专业叫法、主要语言与地区，再按当前缺口选查询；以下表达可以改写为对应语种，不要求逐个执行：

- `领域 + 官方机构 / 学会 / 行业协会 / 数据库 / 目录 / repository / catalog / registry`
- `资源专业名 + 型号/编号 + 作者/机构/制造商`
- `领域 + 图书馆资源指南 / subject guide / 数据门户 / 开放资源`
- `目标 + 来源/参考文献/数据出处/维护者/作者主页`

从官方机构外链、专业文献的资料来源、课程阅读清单、维护者推荐及已确认目录的关联记录继续发现。通过独立来源确认站点身份和覆盖，搜索到自称"官方/最大/最全"的页面不算验证。

如果直接搜资源没有命中，先查该领域用什么术语、目录和发布机制，再回到目标；不要只换同义词重复泛搜。

### 5. 评估新发现的来源

在当前任务中使用前确认：运营/发布主体、主要覆盖、原始出处机制、目标条目是否对应、更新时间和访问条件。大型托管平台还应核验具体上传者。

可以先把新平台用于当前任务，给出实际证据与局限；需要保留跨任务经验时依主技能维护规则执行。记录适用领域、来源角色、标识与术语、有效入口、检查时间及局限，使经验能用于类似资源。

## 二、检索路线

### 1. 把需求变成可核验目标

先确定需要的是哪种产物：事实/记录、原始内容/文件、工具/模型、商品、服务/人员、机会/地点等。列出必须满足的条件与可放宽偏好，明确什么才算成功：找到名字、找到原始出处、得到特定版本、可下载文件、可报名机会或有货的供应方等。

未给出名称时，用功能、主题、情节/图像/声音特征、使用场景、规格或结果描述识别候选。把"识别目标是什么"和"找到哪里能获取"分开进行；证据不足时保留多个候选，不要过早锁定。

### 2. 用来源地图定位领域入口

从上面的"来源角色"出发，回答与本题相关的问题：

| 要弄清什么 | 怎样查 |
|---|---|
| 专业人士怎样称呼它 | 官方文档、专业词表、目录分类、标准术语、技术参数和同类条目 |
| 谁会产生原始资源 | 作者、机构、项目、监管/登记机关、制造商、课程或活动主办者 |
| 谁会编目和保存它 | 领域数据库、专业名录、图书馆指南、登记系统、机构仓储、行业目录 |
| 通过什么渠道获取 | 原发布页、下载/API、借阅、分发商店、经销商、专业市场、申请入口 |
| 哪些线索可以继续追 | 参考文献、依赖、替代型号、关联版本、机构/作者页、分类标签、迁移和历史记录 |

已熟悉且入口明确的领域可以直接检索。陌生领域先用少量发现性查询确定术语和专业入口，核验后进入对应来源；不要一开始穷举所有网站或组合全部查询词。

### 3. 选择查询路线并随结果修正

可从专业目录/编号、生产者、功能/规格、内容片段、关联记录、历史版本、相关社区或不同语言切入。按当前证据选择最有希望的路线，优先补齐决定结果成败的条件。每轮说明要验证的缺口，再根据结果保留、调整或结束该路线。

困难任务可在工作上下文保留以下最少记录，不必每题创建文件或向用户展示台账：

`候选来源/线索 | 为什么值得查 | 查询/动作 | 实际新增信息 | 已解决或剩余缺口 | 下一步`

同一个查询返回空结果只否定这次查询；某个目录的空结果只覆盖它实际收录的范围。工具错误不能用来否定资源存在。

### 4. 建立对象身份与查询变体

建立最少必要字段：

- 名称：专业名/俗称、原名/译名、简繁/转写、简称、旧称、拼写变体。多义词先识别对象类别，别名从可靠条目确认。
- 消歧：作者/生产机构/厂商、年份、地区、版本、适用平台或对象、分类与上下级关系。
- 编号：ISBN、DOI、标准/专利/档案号、设备型号/零件号、包名、数据集/课程/项目号等。确定编号后查编号及对应登记/编目系统，避免同名误命中。
- 特征：功能/规格、主题、材料/变量/研究对象、文件结构、图像/声音片段、正文短句、错误信息等；仅使用必要片段，避免发送敏感内容。
- 获取目标：全文/摘要、原始/加工数据、源文件/预览、具体版本/格式/精度、地区/语种、实物库存/可用服务/仍开放的机会。

不要一开始堆满所有限制。先确定作品，再逐步加约束；结果太少时逐个去掉弱条件，保留真正必须匹配的条件。

### 5. 按失败原因改变搜索方法

| 当前缺口 | 下一步 |
|---|---|
| 对象身份不明或没有条目 | 专业叫法/分类 → 名称/特征/规格 → 生产者 + 时间/地区 → 专业目录关联记录；只有片段时按内容形态考虑短句、反向图像或可用的专业识别工具 |
| 不熟悉这个领域或只知道泛称 | 先找专业术语、主管/生产机构、学会/行业目录、图书馆资源指南和领域数据源，再检索具体目标 |
| 找到条目，没找到发布/获取页 | 追目录外链、生产者主页、机构仓储、分发目录、数据/API入口、发布/登记记录；获取动作词随资源类型调整 |
| 泛搜都是营销、镜像或同名 | 限定官方/专业域；用编号、作者、年份、精确短语；排除词谨慎用，避免过滤真正目标 |
| 通用引擎没有，疑似站内有 | 用站内搜索、分类、标签、作者页、官方 API；需要登录态/动态结果时再选 OpenCLI 或浏览器 |
| 当前语言/地区没找到 | 搜原始生产地语言、领域常用语言、地区译名与转写；专业名和编号优先，必要时查相关地区的发布/登记渠道 |
| 结果反复是同一批页面 | 换不同搜索通道、索引或垂直库；不要只是换一层 AI 摘要；检查新通道实际新增的原始域名和相关条目 |
| 内容下架、页面失效 | 查官方迁移说明、作者新主页、网页档案和目录历史；用快照中的原始标题/链接继续搜当前发布页 |
| 有线索但无法读取 | 区分登录、付费、地区、反爬、工具提取错误；尝试正常可用的替代入口，保留"未读原文"的状态 |
| 内容可获取但不符合条件 | 分别检查版本、时间、语种、格式、精度、授权、兼容性或服务范围；沿关联版本/替代品/原始数据继续找，近似项不算精确命中 |
| 资料存在但无法用正文关键词检索 | 按所在页面、作者/机构、目录字段、附件名或资源编号定位；遇到扫描件、音视频、压缩包内文件等，按需用现有 OCR/转录/文件列表能力检查，不能假装全文已被检索 |

不要为凑流程跑完所有路径；每轮针对真实缺口选择最可能增加信息的一项。

### 6. 沿关联来源继续发现

把新结果中的有用关系作为下一批候选：作者/机构、数据出处、参考文献与被引、项目/产品系列、依赖、替代料号、上下级分类、关联版本、发行/代理渠道、迁移链接等。它们常能带来与初始关键词不同的检索入口。

只追与目标有关的关系。先核对关系是否真实，再决定是否继续；来源间互相转载不算新增独立证据。网页档案用于恢复标题、路径与历史关系，再查当前获取入口。

需要另一搜索通道时，按失败原因选择：不同索引补漏、特定内容生态、专业字段检索、正文提取或实际渲染。能力是否已配置且可用要单独确认，增加 API 名称本身不解决这些缺口。通道选择见 [search-tools.md](search-tools.md)。

### 7. 结果证据与状态

按目标合并重复项，保留不同版本；多个引擎返回同 URL 不算多个结果，多个转载不算独立证据。规范化链接时保留作品/版本标识等必要参数。

| 状态 | 必须实际确认什么 |
|---|---|
| 条目/对象已确认 | 名称、生产者/年份/编号/规格等与目标一致 |
| 入口已找到 | 有对应发布/获取/购买/申请/服务页面或明确的原始链接 |
| 页面可访问 | 实际打开目标页，内容与标题/摘要一致；不是失效页或跳转广告 |
| 获取条件已验证 | 实际验证所需内容可读/获取，或实物/服务/机会当前可用及其条件；说明验证范围，按钮、文件名或 HTTP 200 不够 |
| 尚未验证 / 受限 / 失效 | 明确已完成哪一步、阻碍是什么，提供仍有帮助的条目与下一条可行动线索 |

按任务需要的深度验证即可。用户只要出处时不必下载大文件；用户要可用文件时，不能止于一个未经检查的搜索摘要。下载、执行、安装、购买分别按用户授权和现有环境权限处理。

文件资源核对原发布者、版本、发布日期、格式和声明的大小；有官方校验值时可核对一致性。校验值匹配证明文件一致，不自动证明内容安全。素材用途相关时，核对原文件的许可与署名要求。

### 8. 检查覆盖并交付

- 满足用户约束且证据足够时停止；无需凑平台数量或重复查权威事实。
- 困难搜索在报告未找到前检查：对象/类别是否识别；领域的专业叫法和编号是否尝试；原生产者及相关编目/分发来源是否覆盖；必要的语言/地区/版本变体是否检查；高价值关联线索是否跟进；现有适合的替代通道是否可用。
- 上述项目按相关性适用，不要求简单任务全做。高价值缺口尚可推进时继续；受访问、工具或预算限制时明确标记未覆盖项。连续两轮无新增可用于调整路线和判断成本，不能单独证明找全。
- 未找到时写"在已覆盖的 X 范围未找到匹配 Y 的可用入口"，列出近似匹配及差异，不写"全网没有"。
- 工具故障、访问限制和资源本身不存在分开报告。网页档案能证明历史发布，不保证今天仍能获取。

复杂资源汇报可用：对象/版本 | 原生产者与链接 | 匹配条件 | 已验证状态 | 访问条件/缺口 | 核查时间。简单任务直接给最合适的结果与必要限制。

### 9. 让经验能迁移到其他任务

任务结束时，区分失败出在对象识别、领域来源、索引覆盖、查询、访问、解析还是匹配验证。可复用的经验应包含"哪类资源、专业术语/编号、哪个来源角色、有效入口与访问方式、为什么有效、何时核验及局限"，而不是只记一个网站名。

跨任务持久化仍遵守主技能的维护授权规则；临时网页和凭据不写入经验库。检验维护效果时使用 [tests/eval/methodology.md](../tests/eval/methodology.md) 的已知目标与保留领域测试，不把文档检查当成实际找回能力。
