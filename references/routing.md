# 领域路由：专科检索策略

本文件是 SKILL.md §2 的展开。每个领域给三样东西：**去哪找**（一手源与端点）、**怎么问**（检索式顺序）、**别踩什么**（坑）。

通用原则：先精确标识符，再名称，再语义描述。标识符命中率最高，语义检索只在没有标识符时用。

---

## academic — 学术与文献

**一手源**

| 源 | 端点 | 用途 |
|---|---|---|
| OpenAlex | `api.openalex.org/works?search=` / `filter=doi:` | 元数据、引用数、开放获取状态，免费无限 |
| Crossref | `api.crossref.org/works?query.bibliographic=` | DOI 权威登记，出版社元数据 |
| arXiv | `export.arxiv.org/api/query?search_query=` | 预印本全文 |
| Semantic Scholar | `api.semanticscholar.org/graph/v1/paper/search?query=` | 引文图（citations / references） |
| PubMed | `eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi` | 生物医学 |
| Unpaywall | `api.unpaywall.org/v2/<doi>?email=` | 找合法免费全文 |
| 中文库 | CNKI / 万方 / 维普 | 需机构授权 |

**检索顺序**

1. 题名或 DOI 精确匹配
2. 作者 + 年份
3. 引文向前（谁引了它）/ 向后（它引了谁）
4. 综述与系统评价补全景
5. 只有到这时才用语义检索兜底

**坑**

- Google Scholar 触发人机验证，不适合脚本化；用 OpenAlex/Crossref 替代。
- 预印本未评议，结论强度低于期刊版；同一工作常有多个版本，核对版本号与日期。
- 掠夺性期刊：看是否在 DOAJ、是否有可查的同行评议流程。
- 中文库全文要求授权；"知网全文检索"类第三方服务大多无授权，宣传不可信。

## engineering — 工程与技术

**一手源**

| 源 | 入口 | 用途 |
|---|---|---|
| 官方文档 | 项目官网 / docs 子域 | 唯一权威的 API 与行为说明 |
| GitHub | `gh search repos/code/issues`、`gh api` | 版本、star、license、issue 历史、release notes |
| 包注册表 | npm / PyPI / crates.io / Maven | 版本、依赖、发布时间 |
| 硬件 | 厂商 datasheet、Mouser / DigiKey、NVIDIA NGC catalog | 规格、封装、驱动要求 |

**检索顺序**

1. 错误原文加引号精确搜
2. 版本号 / commit hash
3. issue / PR / release notes
4. 官方 changelog 与迁移指南
5. 社区讨论（StackOverflow、Reddit、V2EX）仅作线索

**坑**

- AI 生成的"教程"博客大量存在，内容常与当前版本不符。
- 版本错配是最常见误判：先确认答案对应的版本，再看是否适用。
- `gh search repos` 对口语化短语召回差，改用 API 遍历 forks 或 raw 文件比对。
- 驱动/依赖要求以官方 Dockerfile 或 lock 文件为准，不以博客为准。

## product — 商品与消费

**一手源**：厂商官网规格页、官方旗舰店、授权经销商。

**独立实测**：Wirecutter、Consumer Reports、Which?、Serious Eats、少数派（sspai）。

**检索顺序**

1. 官方规格与型号确认
2. 独立实测（有测试方法与数据）
3. 真实长期使用讨论（Reddit / 专业论坛）
4. 价格：官方店与授权经销商，核对型号、地区、税运、库存、查询时间

**坑**

- 电商评论不作为口碑依据；电商只用于确认目标后的价格与交易条件。
- 中文"横评"大量为 AI 批量生成营销稿：单品牌强推、参数夸张、无实测、带引流。
- 佣金链接媒体与会员制独立评测要区分。
- 英文源基本不覆盖国产品牌，反之亦然。

## business — 商业与公司

**一手源**

| 源 | 入口 | 用途 |
|---|---|---|
| SEC EDGAR | `efts.sec.gov/LATEST/search-index?q=` | 美股公司原始披露（10-K/10-Q/8-K） |
| 巨潮资讯 | `cninfo.com.cn` | A 股公告 |
| 港交所披露易 | `hkexnews.hk` | 港股公告 |
| 公司 IR | 官网 investor relations | 年报、业绩会材料 |
| 工商登记 | `gsxt.gov.cn`、`creditchina.gov.cn` | 主体存续、股东、行政处罚 |

**检索顺序**

1. 主体确认（统一社会信用代码 / CIK / 股票代码）
2. 原始披露文件
3. 第三方口径回溯到原始表

**坑**

- 天眼查/企查查数据经过加工且需登录，关键结论回到工商原始登记核验。
- 估值、融资额、市占率三个数字在不同来源常口径不一，必须写明来源与口径。
- 已注销/吊销主体仍在三方站显示"存续"，以官方登记为准。

## legal — 法规、标准与合规

**一手源**

| 源 | 入口 | 用途 |
|---|---|---|
| 国家法律法规数据库 | `flk.npc.gov.cn` | 法律、行政法规、司法解释现行文本 |
| 国务院政策库 | `gov.cn` | 政策文件、部门规章 |
| 全国标准信息公共服务平台 | `std.samr.gov.cn` | 国标/行标编号、状态、全文 |
| 地方门户 | 各省市政务服务网 | 地方实施细则与执行口径 |

**检索顺序**

1. 文号 / 标准号精确匹配
2. 现行性（是否废止、被修订）
3. 修订沿革（哪一版适用）
4. 地方实施细则与主管部门答复

**坑**

- 转载站长期保留旧版，"最新版"标题常与正文不符。
- 同一事项各地执行口径可能冲突（如某类经营场所是否需卫生许可），必须落到具体地市。
- 标准全文分"公开"与"需购买"，未读到全文不得引用具体条款。
- 法律适用问题不能只靠检索，涉及争议时说明"需专业人士确认"。

## local — 本地服务与线下资源

**一手源**：政府服务门户（如浙里办）、主管部门公告与许可名单、行业协会、商户官方公众号/小程序。

**检索顺序**

1. 地名 + 服务类型 + 主管部门
2. 行政许可公示 / 备案名单
3. 商户自述与地图 POI

**坑**

- 点评类平台（大众点评、美团）的评分与探店内容大量为商业合作。
- "某某之最/第一"的自称不能作为事实。
- 营业状态（是否仍在营）以近期官方或地图 POI 更新时间为准。

## media — 作品与内容

**一手源**：发行方官网、Bangumi（动画）、MusicBrainz（音乐）、SteamDB / PCGamingWiki（游戏）、TMDB（影视）、国家图书馆（出版物）。

**检索顺序**

1. 原名（母语原名优先）
2. 地区译名 / 别名
3. 版本与平台
4. 社区 wiki 补细节

**坑**

- 盗版站与聚合站的元数据常错配（封面、年份、集数）。
- 上下架状态随地区变化，需写明查询地区与时间。
- 社区 wiki 是一手经验不是官方规格。

## data — 数据集与统计

**一手源**

| 源 | 端点 | 用途 |
|---|---|---|
| 国家统计局 | `data.stats.gov.cn` | 中国官方统计 |
| World Bank | `api.worldbank.org/v2/` | 国际可比指标 |
| DataCite | `api.datacite.org/dois` | 数据集 DOI 登记 |
| Zenodo / Figshare | `zenodo.org` / `figshare.com` | 研究数据仓储 |
| 专业门户 | OECD、IMF、各国统计局 | 领域专用 |

**检索顺序**

1. 指标定义（这个数到底测什么）
2. 口径、时间范围、空间范围
3. 原始表（不是聚合图）
4. 许可证与引用要求

**坑**

- 二手聚合站会改口径、补缺失值、平滑异常，必须回溯原始表。
- 分辨率与覆盖率常被省略（如"全国"实为"城镇"）。
- 数据集版本更新后旧 DOI 仍可访问，需确认版本号。

## general — 无固定一手源时

1. 用 ddgs 做来源发现：先找"这类东西由谁生产、谁编目、谁分发"。
2. 从结果中识别 2–3 个候选一手源。
3. 进入候选源核验（发布者、覆盖范围、更新频率）。
4. 确认后按对应领域的策略走，并在汇报里说明最终落在哪个领域。

通用搜索只是入口发现器。停留在结果页、把摘要当结论，是本领域最常见的失败。
