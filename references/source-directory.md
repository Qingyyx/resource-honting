# 跨领域来源发现

本表帮助判断资源通常如何产生、编目与分发，并据此发现适合当前任务的具体平台。任何领域都按同一套方法选择来源；表内示例仅为入口提示，实时可用性、权限与目标覆盖需要核查。

## 一、先判断来源的角色

| 来源角色 | 应找谁 | 能解决什么 |
|---|---|---|
| 生产与发布 | 作者、开发者、研究团队、制造商、发行方、政府或公共机构 | 原始名称、版本、发布信息、规格、数据与获取入口 |
| 编目与标识 | 图书馆、登记系统、专业数据库、标准组织、行业名录 | 确认身份、专业叫法、编号、作者机构、关联版本 |
| 分发与获取 | 仓储、软件注册表、数据门户、商店、馆藏、专业市场、服务机构 | 实际内容、文件、库存、服务范围、费用和访问条件 |
| 使用与维护 | 专业协会、领域社区、使用者、维护者、问题追踪器 | 替代名称、兼容性、实际经验、迁移位置和修复线索 |
| 历史与归档 | 发布历史、旧目录、网页档案、历史馆藏、迁移公告 | 旧名称、失效链接的出处、历史存在与版本关系 |

同一站点可能承担多个角色。编目记录不等于已经取得资源，使用经验也不等于官方规格；按当前缺口选择需要的角色。

## 二、按资源形态找入口

| 资源形态 | 优先找什么来源 | 身份与匹配线索 | 获取时核对 |
|---|---|---|---|
| 论文、报告、研究证据 | 作者/机构、学科库、期刊会议、资助项目、机构知识库 | 题名、作者、DOI、课题号、研究类型 | 全文/摘要、版本、评议状态、适用范围；深研见 deep-research-sources.md |
| 统计、数据集、表格、地图 | 数据生产机构、政府/专业数据门户、研究仓储、地理数据中心 | 指标、变量、空间范围、时间、数据集编号/DOI | 口径、覆盖、分辨率、更新、格式、许可证、下载或 API |
| 法规、标准、专利、公共记录 | 制定机关、标准组织、专利局、登记/披露机构 | 编号、名称、法域、实施/申请日期、主体 | 现行状态、全文范围、修订与法律/地区适用条件 |
| 软件、代码、模型、插件、固件 | 维护者主页/仓库、官方注册表、模型仓库、硬件支持页 | 包名、版本、模型/设备型号、依赖、许可证 | 平台架构、兼容性、发布者、原始文件、权重与代码是否齐全 |
| 手册、图纸、维修资料、工业部件 | 制造商、专业分销商、工程目录、维修/行业社区 | 型号、硬件修订、零件号、图号、接口规格 | 原理图/数据表/用户手册的区别，适用修订、尺寸、库存和地区 |
| 图书、档案、古籍、文献版本 | 出版社、图书馆、联合目录、档案馆、作者机构 | 作者、ISBN、版次、馆藏/档案号、语言、年代 | 元数据/目录/全文、借阅或访问方式、缺页与扫描质量 |
| 课程、教材、教程、考试与培训资料 | 授课机构、教师、课程项目页、开放课程目录、专业认证机构 | 课程号、讲师、学期、级别、考纲版本 | 大纲/视频/作业是否齐全、语种、先修要求、现行考纲和费用 |
| 图片、音频、视频、字体、3D/CAD、模板与设计资产 | 原作者、机构开放馆藏、对应类型的专业素材库和市场 | 作者、作品名、目录号、视觉/声音片段、文件特征 | 原文件/预览、格式、清晰度、可编辑性、适配软件、用途授权 |
| 影视、音乐、游戏及文化作品 | 作者/制作发行方、作品目录、发行平台、相关社区 | 原名、地区译名、作品编号、年份、版本、人物/情节特征 | 目录/本体/衍生内容、地区、语种、上下架、访问与购买条件 |
| 商品、设备、供应商与实物 | 制造商、专业渠道、行业名录、经销商、交易平台 | 品类专业名、型号、规格、替代料号、行业术语 | 供应主体、库存、起订量、交付地区、总价与适配性；电商评价沿用主技能约定 |
| 专家、机构、服务与解决方案 | 专业组织、机构官网、人员/服务目录、成果与项目记录 | 问题领域、资质、地域、对象、成果、服务范围 | 身份、实际能力、近期活动、可用服务和利益关系 |
| 职位、活动、项目机会、场地与本地资源 | 主办/招聘/管理方、政府/公共服务入口、专业与地区平台 | 地区、日期、主办方、职位/项目号、设施或服务类型 | 是否仍开放、名额、地点、资格、开放时间与申请方式 |

遇到表外资源时，仍从“谁生产、谁编目、谁分发、谁使用”建立来源路线。不同资源可以组合多个行，例如找设备维修课程同时涉及设备型号、课程目录和技术社区。

## 三、从领域知识发现具体来源

先提取领域专业叫法、主要语言与地区，再按当前缺口选查询；以下表达可以改写为对应语种，不要求逐个执行：

- `领域 + 官方机构 / 学会 / 行业协会 / 数据库 / 目录 / repository / catalog / registry`
- `资源专业名 + 型号/编号 + 作者/机构/制造商`
- `领域 + 图书馆资源指南 / subject guide / 数据门户 / 开放资源`
- `目标 + 来源/参考文献/数据出处/维护者/作者主页`

从官方机构外链、专业文献的资料来源、课程阅读清单、维护者推荐及已确认目录的关联记录继续发现。通过独立来源确认站点身份和覆盖，搜索到自称“官方/最大/最全”的页面不算验证。

如果直接搜资源没有命中，先查该领域用什么术语、目录和发布机制，再回到目标；不要只换同义词重复泛搜。

## 四、已有入口示例

| 来源类型 | 可用作起点的示例 | 注意 |
|---|---|---|
| 统计与公司原始披露 | 国家统计局、对应部委、World Bank、公司 IR、巨潮、披露易、SEC EDGAR | 原始表和公告优先，聚合/估算需回溯 |
| 学术与科学数据 | 学科专属库、Crossref、DataCite、Zenodo、机构知识库 | 目录、引文、全文与原始数据各自核对 |
| 软件与模型 | 项目官网、维护者 GitHub/GitLab、对应包注册表、Hugging Face | 核验具体维护者、发布记录、版本与依赖 |
| 图书与档案 | 出版社、国家图书馆、WorldCat、Internet Archive、Project Gutenberg | 馆藏和快照不保证全文当前可获取 |
| 创作资产 | 作者站点、Wikimedia Commons、Openverse、专业资产库 | 核对原文件页和逐项授权 |
| 文化作品与社区 | 发行方、Bangumi、MusicBrainz、SteamDB、PCGamingWiki、专业 Wiki | 分别用于身份、目录、历史或经验，不作整个平台的可信保证 |

示例不是白名单，也不是每次必须访问的清单。其他领域优先按前述方法现场发现其专业来源，而非强行套用熟悉的平台。现有源的判断参考 [platform-trust.md](platform-trust.md)。

## 五、评估新发现的来源

在当前任务中使用前确认：运营/发布主体、主要覆盖、原始出处机制、目标条目是否对应、更新时间和访问条件。大型托管平台还应核验具体上传者。

可以先把新平台用于当前任务，给出实际证据与局限；需要保留跨任务经验时依主技能维护规则执行。记录适用领域、来源角色、标识与术语、有效入口、检查时间及局限，使经验能用于类似资源。
